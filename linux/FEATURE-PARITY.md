# Linux feature parity and release gate

The target is the complete Nashi experience. This file explicitly separates implemented Linux operations from remaining parity work; catalog availability alone is not validation.

| Area | Linux adaptation | Remaining for full parity |
| --- | --- | --- |

| Images | Original PhotoCodec/PhotoAdjustments; image conversion, resize/rotate/flip, compression targets; crop coordinates/drag, eight resize handles and aspect presets; annotation tools with independent selection/move/resize, undo/redo and per-mark deletion; multi-area redaction with move/resize/list/undo, live solid/blur/pixelate previews and local OCR word detection; frame/collage; PDF creation | Compare shared frame/collage options and previews; broader real-world OCR/redaction fixtures; face assistance; compare annotation rendering and interactions across real desktop sessions |

## Validation evidence

- Native x64 and cross-compiled ARM64 Linux builds succeed with warnings treated as errors. Native Ubuntu 22.04 x64 and Ubuntu 24.04 ARM64 CI builds also succeed.
- Launching the installed app from a second process forwards to the existing window; only one installed Nashi process remains. This was checked across separate command sessions on the development Wayland desktop.
- `linux/Nashi.Linux.Verify`: 90 checks on the development machine (ExifTool unavailable), including real image dimensions/pixels, original hashes, PDF page counts/rendering, archive/subtitle round trips, QR, cancellation, real FFmpeg conversion/trim and LibreOffice TXT → DOCX → PDF → TXT text preservation. Additional checks cover real Tesseract word detection, source-coordinate/padded TSV parsing and limits, multi-area solid/blur/pixelate exports, unchanged outside pixels, fractional bounds, transparent pixels, invalid inputs and cancellation. ExifTool write/remove/conversion-tag checks run when available.
- `windows/Nashi.Verify` on Linux with system FFmpeg/ffprobe: 1,417 shared engine/security checks pass. This is existing Nashi code, not a claim about the Windows GUI running on Linux.
- `Nashi --smoke-test`: 332 assertions in real Avalonia Linux windows, covering profile persistence/isolation/validation/Reset and format-specific Settings controls, partial-move UI/Library results, real FFmpeg filmstrip/waveform generation, processed-file artwork replacement, rapid preview switching, separate processed/source ranges, Reset and bitmap cleanup, OCR language selection/cancellation/Clear/Reset, independent redaction regions and numeric edits, live blur/pixelate and original comparisons, dialog export options, live edit/frame previews, annotation pixel exports, independent line/freehand transforms, undo/redo/delete/list routing, marker multiply blending, magnifier source/clipping, source-bound/aspect crop geometry, routed crop resize/move/new-selection, numeric crop changes, Float drop/deduplication/collapse and Home/editor construction, PDF thumbnails, metadata values, libmpv playback/seek, URI filtering and Ctrl/Shift/Alt routed drag/drop events. Captures light/dark/compact/editor/wheel PNGs. The drag tests inject application events, not operating-system input; they do not establish real global file-manager integration. Only the emitted successful `smoke.json` is evidence of a completed run.

[Linux CI at 5e9191c](https://github.com/uahadov/nashi-app/actions/runs/40718761396) executes 1,327 shared checks, 43 Linux export/integration checks (including ExifTool and LibreOffice), and 29 native UI assertions on both x64 and ARM64. Both runners build AppImage/tar/deb/rpm packages and upload package/UI evidence. Xvfb routed drag tests still do not validate a real user file-manager session. Successful package installation across target distributions must be linked before promoting this branch to a feature-complete Linux release. Remaining cells above are release blockers, not optional differences to silently omit.

The UI smoke process now returns a nonzero exit status on caught assertion/fixture failures. CI deliberately supplies an invalid image output fixture and requires both the failure marker and nonzero status, preventing a logged exception from being treated as success. [Crop CI at afa1f72](https://github.com/uahadov/nashi-app/actions/runs/40721656336) passes on both Linux architectures, including 204 UI/geometry assertions and the deliberate-failure regression. [Annotation CI at f8a5d32](https://github.com/uahadov/nashi-app/actions/runs/40726768534) passes on both architectures with 271 UI assertions. [Redaction/OCR CI at d78fb8c](https://github.com/uahadov/nashi-app/actions/runs/40782789326) passes the shared engines, Linux exports and 302-check native UI stages on both architectures; packaging completed on both architectures. [Media-artwork CI at 5d912df](https://github.com/uahadov/nashi-app/actions/runs/40783305373) failed at audio waveform loading on both runners with no audio device. [The null-sink and processed-range follow-up at d1b0f95](https://github.com/uahadov/nashi-app/actions/runs/40783732021) passes x64 CI including packaging; ARM64 UI validation is pending. Hosted UI smoke checks use libmpv's null audio sink because runners have no sound device. They validate decoding, playback timing and waveform generation, not physical speaker output. Normal launches retain system audio output.

## Current integration

The Linux branch incorporates upstream `2143869` (Nashi 0.7.11), including document/EPUB, localization and media fixes. The linked original DocumentConversion now calls a platform image-crop adapter; Poppler renders only the requested PDF pages with the original 512 MB aggregate PNG budget. Five Linux checks validate selected page indices, dimensions/content, cropping and cancellation. The original arbitrary 500-page Linux rendering cap is replaced by the shared aggregate output budget.

The transfer CI at 7fadebc passed x64 (including 88 Linux checks and 317 UI checks) but ARM64 timed out after audio-to-video rapid preview replacement. The latest Linux player uses libmpv asynchronous commands and observed properties instead of blocking the UI on synchronous command/property requests. All 331 UI assertions pass locally with the integration; ARM64 hosted validation is still required. Per-format settings and editor profile changes also need hosted validation.

The 9bd7ee3 ARM64 run no longer froze the UI, but timed out waiting for a zero cached duration after rapid preview replacement. The next change explicitly refreshes observed properties asynchronously on FILE_LOADED, because observations may suppress unchanged values; a same-file repeated-load regression is included. Local native UI checks pass 332 assertions. Hosted validation of this fix remains required.
